# Wicket Oat Components

Use `Oat.Components` for a "Fast Path" to build UI with encapsulated markup.

## Variants
Colors are a single `dev.jbaby.wicket.oat.OatVariant` enum everywhere (alerts, badges, buttons, toasts): `DEFAULT`, `SECONDARY`, `SUCCESS`, `WARNING`, `DANGER`. Buttons style `SECONDARY`/`DANGER`; badges all; alerts and toasts `SUCCESS`/`WARNING`/`DANGER`. There are no per-component `Variant` enums.

## General
- `alert(id, message?, variant?)`: Creates an `OatAlert`. `message`/`variant` can each be a plain value, an `IModel`, or omitted.
- `badge(id, label, variant?)`: Creates an `OatBadge`. `label` can be a `String` or an `IModel<?>`.
- `button(id, label, onClick)`: Creates an `OatButton` with an Ajax click handler, on an `<a>` or `<button>`. The label is rendered as the tag's text, so the markup is just `<a wicket:id="save"></a>` (no inner `<span wicket:id="label">` - that now fails). `new OatButton(id) { onClick... }` without a label renders the markup body instead, e.g. an icon with `setIcon(true)`.
- `splitButton(id, label, onClick)`: `OatSplitButton`, a button for the usual action joined to a "▾" button with a menu of related ones (Oat's `menu.buttons`). `addAction(label, target -> ...)` returns the entry for `.setVariant(OatVariant.DANGER)`; `setVariant`/`setStyle`/`setSize` apply to both buttons. The "▾" button is named by the `OatSplitButton.more` resource ("More actions").
- `submitButton(id, label, onSubmit, onError?)`: Creates an `OatSubmitButton`, an Oat-styled `AjaxButton` that submits its form: `onSubmit` runs when the form is valid, `onError` when it isn't (e.g. `target -> target.add(form)` to show inline errors). Markup: `<button wicket:id="save"></button>`. Subclass `OatSubmitButton` directly to override `onSubmit`/`onError` instead.
- For slow actions, `setBusyIndicator(true)` on either button (off by default) shows a spinner (`aria-busy`) while its Ajax request runs and ignores further clicks, so the action can't run twice. `OatDialog.setBusyIndicator(true)` does it for the dialog's confirm button, and `Oat.Behaviors.ajaxBusy()` for other Ajax links and buttons.
- `card(id)`: Creates an `OatCard` container.
- `avatar(id, urlModel)` / `avatar(id, initials)`: Creates an `OatAvatar` from just an image URL or just initials.
- `avatar(id, urlModel, initials, size)`: Creates an `OatAvatar` with both an image and initials fallback; `size` is required in this overload.
- `avatarGroup(id, model, size?, populateItem)`: Creates an `OatAvatarGroup` (a clustered/overlapping set of avatars).
- `emptyState(id, title, message?)`: Creates an `OatEmptyState` placeholder.

## Layout & Navigation
- `accordion(id, model, exclusive?, populateItem)`: Creates an `OatAccordion`.
- `buttonGroup(id, model, populateItem)`: Creates an `OatButtonGroup` container for buttons.
- `breadcrumb(id, model, populateItem)`: Creates an `OatBreadcrumb` trail.
- `pagingNavigator(id, pageable)` / `ajaxPagingNavigator(id, pageable)`: `OatPagingNavigator` / `OatAjaxPagingNavigator`, Wicket's (Ajax)`PagingNavigator` rendered as Oat pagination for any `IPageable` (`DataView`, `PageableListView`, `DataTable`). Prefer these whenever there is an `IPageable`. For the Ajax one, the pageable or a parent needs `setOutputMarkupId(true)`.
- `pagination(id, model, populateItem)`: Creates an `OatPagination` control - hand-rolled page links for when there's no `IPageable`; you style the current page yourself.
- `dropdown(id, triggerLabel, model, label, onClick)`: Creates an `OatDropdown` popover menu whose items show `label.apply(item)` and run `onClick(target, item)` over Ajax when chosen; the menu then closes.
- `dropdown(id, triggerLabel, model, populateItem)`: The same with items you populate yourself (each is a `<button role="menuitem">` with a `"label"` child); call `dropdown.close(target)` after handling a click.
- `tabbedPanel(id, tabs)`: Creates an `OatTabbedPanel`, Wicket's `AjaxTabbedPanel` with Oat styling. Tabs are `ITab`s - build them with `Oat.tab("Title", SomePanel::new)` (the factory receives the panel id). Only the selected tab's panel is created, and switching swaps it over Ajax; `new OatTabbedPanel<>(id, tabs, selectedIndexModel)` keeps the selection in your own model. Prefer this for panels that are expensive or need server state.
- `tabs(id, model, populateTab, populatePanel)`: Creates an `OatTabs` tab strip + panels, all rendered up front and switched in the browser by the `ot-tabs` web component.
- `dialog(id, header)` / `dialog(id, triggerLabel, header)`: Creates an `OatDialog` modal on the native `<dialog>` element. Open and close it from any Ajax handler with `dialog.open(target)` / `dialog.close(target)` (`open` re-renders it first); with a trigger label it also renders a button that opens it natively. Set the body with `setBody(component)` - the component must use the id `OatDialog.BODY_ID`. The body sits in the dialog's own form, so fields in it are validated when Confirm is clicked: on a validation error the dialog stays open and shows them inline; otherwise the overridable `onConfirm(target)` runs and the dialog closes unless an error was reported in it there (e.g. `field.getField().error("Taken")`). `setConfirmLabel`, `setCancelLabel` and `setConfirmVariant(OatVariant.DANGER)` customize the buttons; the default labels come from the `OatDialog.confirm` / `OatDialog.cancel` resource keys.
- `pageHeader(id, title)`: `OatPageHeader`, a `Border` on a `<header>`: breadcrumb, title (`<h1>`, looked up by id when no title is given) and subtitle on one side, and the tag's own content as the actions on the other (wrapping below on narrow screens). `setSubtitle(...)`, `setBreadcrumb(List<MenuItem> | IModel<List<MenuItem>>)` - links to the pages above, ending with the title as the current page (`aria-current`), in a `<nav>` named by the `OatPageHeader.breadcrumb` resource.
- `popover(id, triggerLabel, id -> content)`: `OatPopover`, a button opening a panel with any content (an `ot-dropdown` with a popover), e.g. a filter or quick-edit form; the factory must use the id it is given (`OatPopover.CONTENT_ID`). `close(target)`, `getContent()` to re-render it, `getTrigger()`.
- `wizard(id, target -> onFinish)` / `new OatWizard(id) { onFinish(target) }`: a form over several steps with numbered steps (`aria-current="step"`; finished steps are links back). `addStep(title, id -> component)` - created when the step is shown, so keep data in a shared object; it is rendered on a `<div>`. Next validates the step's fields inline (Enter does the same; Finish on the last step); Back and step numbers go back without validating. Override `onNext(step, target)` and report an error on a component to keep the user on a step. `getCurrentStep()`/`setCurrentStep(i)`. Texts: `OatWizard.back`/`.next`/`.finish`, step list named by `OatWizard.steps`.
- `loginForm(id, (user, pass) -> boolean)` / `new OatLoginForm(id) { signIn(user, pass, rememberMe) }`: username (`autocomplete="username"`), password (`current-password`), Sign in (busy). A failed attempt shows `OatLoginForm.failed` without saying which part was wrong and clears the password; a successful one calls `getSession().replaceSession()` and `onSignedIn(target)` (default: `continueToOriginalDestination()`, then the home page). `setRememberMe(true)` shows the checkbox, `setForgotPasswordLink(PageClass)` a link. The core doesn't depend on `wicket-auth-roles`; call e.g. `AuthenticatedWebSession.get().signIn(...)` in `signIn`.
- `crud(id, columns, provider, rowsPerPage)`: `OatCrud<T, S>`, an `OatDataTable` plus "New" (with `setNewItem(Supplier)`), Edit and Delete in an actions column, an edit `OatDialog` and an `OatConfirmDialog`. `setEditor((id, model) -> panel)`: the panel gets a `CompoundPropertyModel` over the record (pass it to `super(id, model)`; Oat fields named after properties bind by themselves). `onSave((target, record) -> ...)` runs after a valid save (report an error on a field to keep the dialog open), `onDelete(...)` after confirming; `setTitle(Record::name)` names it in "Edit {0}" / "Delete {0}?"; `setSearch(id -> component)` beside "New"; `getDataTable()`, `create(target)`, `edit(target, record)`. Edits load the record via `provider.model(...)`. Texts `OatCrud.*`.
- `tree(id, ITreeProvider)`: `OatTree<T>` (`components.tree`), Wicket's `NestedTree` styled with Oat (`.oat-tree`, no theme images). `setLabel(fn)`, `setIcon(node -> iconName)`, `onSelect((target, node) -> ...)` (labels become links, `aria-current` on the selected one; `select(target, node)`). Expand buttons are `<button>`s with `aria-expanded` and `OatTree.expand`/`collapse` labels ("Expand {0}"). Nodes are compared by the provider's models (`equals`).
- `tableTree(id, columns, ITreeProvider, rowsPerPage)`: `OatTableTree<T, S>`, a tree grid (Wicket's `TableTree`); put a `new TreeColumn<>(Model.of("Name"))` among the columns, other columns as in a data table. Oat headers (`aria-sort` with an `ISortableTreeProvider`), paging, `OatTableTree.empty`; `setLabel`, `setIcon`, `onSelect`. Focus returns to a node's button after toggling.
- `menuBar(id)`: `OatMenuBar`, a row of small ghost buttons (`setStyle(ButtonBehavior.Style)` to change). `addAction(label, target -> ...)`, `addLink(label, PageClass[, params])` (it has `aria-current` while that page is shown), `addMenu(label)` returns a `Menu` with `addAction(label, ...)` / `addAction(IModel label, OatVariant.DANGER, ...)`. Put it on a `<nav aria-label="...">`.
- `splitLayout(id, id -> first, id -> second)`: `OatSplitLayout`, two panes, each scrolling on its own. The first is resizable with the browser's own corner handle (CSS `resize`, no JS). `setSplit(20..80 in steps of 10)` sets its starting share; `setOrientation(VERTICAL)` stacks them (28rem high by default). Below 768px they are stacked and not resizable. The factories must use the ids they are given (`first`, `second`).
- `masterDetail(id, selectionModel)`: `OatMasterDetail<T>`, a list beside the selected item's details. `setMaster(id -> component)` (any component; it calls `select(target, item)` and can use `isSelected(item)`), `setDetail((id, itemModel) -> component)`; an empty state (`OatMasterDetail.empty`) while none is selected. Below 768px one shows at a time, with a Back button (`OatMasterDetail.back`, `showList(target)`); switching keeps the list's scroll position.
- `confirmDialog(id)`: `OatConfirmDialog`, an `OatDialog` that asks before an action runs. Add one per page and call `confirm.ask(target, header, message, t -> action)` from any Ajax handler (`String` or `IModel<String>` texts; `message` may be `null`); the action runs on Confirm, at most once, and Cancel/Escape closes without running it. One dialog serves any number of buttons. The confirm button is `DANGER` by default; `setConfirmLabel`, `setCancelLabel`, `setConfirmVariant`, `setHeader` and `setBusyIndicator` return `OatConfirmDialog`, so they chain with `ask`.
- `OatAppLayout`: (Base Page) Provides sidebar and topnav, and applies the current theme. Subclasses pass `PageParameters` (or a model) to `super(...)`; override `sidebarMenuItemsModel()` to return `MenuItem`s - `MenuItem.of(label, PageClass)` or `MenuItem.of(label, PageClass, pageParameters)`, with a `String` or `IModel<String>` (e.g. `ResourceModel`) label. `MenuItem.group(label, items...)` makes a collapsible section of links (open while one of its pages is shown; groups can't be nested), and `item.withBadge(IModel<?> | String)` adds a badge after a link's label, read on every render and hidden while `null`, empty or zero (e.g. `withBadge(() -> orders.countOpen())`). The sidebar has a markup id, so `target.add(sidebar)` re-renders it, e.g. to update badges. Items for pages the user isn't authorized to instantiate are left out (and a group left empty), and an item is active when the page class (and its parameters, if any) match. The title, name and menu-button label default to the `OatAppLayout.title` / `OatAppLayout.name` / `OatAppLayout.toggleMenu` resources; override `appTitleModel()`/`appNameModel()`, `createTopNavExtra(id)` and `createFooter(id)` to customize.

## Form Components
- `multiSelectField(id, label, IModel<List<T>>)`: `OatMultiSelectField<T>`, an `OatCustomField` with chips (remove buttons named `OatMultiSelectField.remove`) and a search box (Wicket's `AutoCompleteTextField`): `setChoices(text -> list)`, `setDisplay(fn)`, `setMaxChoices(n)`. Choosing adds the value and clears the box; chosen ones aren't suggested again. Required means at least one. Not inside a modal `OatDialog` (the suggestion list goes into `<body>`), same as `OatAutoCompleteField`.
Most form components are available via `Oat.Components.[type]Field` and produce an `Oat[Type]Field`, but a few don't follow the `Field` naming: `textArea` → `OatTextArea`, `dropdownChoice` → `OatDropdownChoice`, `checkBox` → `OatCheckBox`, `oatSwitch` → `OatSwitch`, `fileUpload` → `OatFileUpload`, `fileDropzone` → `OatFileDropzone`, `tagInput` → `OatTagInput`.

Every one takes an optional trailing hint-text model — but only when `label` is passed as an `IModel<String>`, not a plain `String`:
`Oat.Components.[type]Field(id, IModel<String> labelModel, model, hintModel?)`. There is no `(id, String label, model, hintModel)` overload; wrap the label in `Model.of("Label")` if you need a hint.

The label and the model can also be left out, exactly like plain Wicket form components: `[type]Field(id)` / `new Oat[Type]Field(id)` inherits the model from a parent `CompoundPropertyModel` by id, and `[type]Field(id, model)` / `new Oat[Type]Field(id, model)` keeps an explicit model. A missing label is looked up in the `.properties` files with the id as the key (falling back to the id). `dropdownChoice` mirrors `DropDownChoice`: `(id, choices, renderer?)` and `(id, model, choices, renderer?)`.

Behavior of the field panels:
- Required fields get `aria-required="true"` and an asterisk after their label (via `data-required` on the field container). The native `required` attribute is deliberately not set, since the browser would block the submit with its own message before Wicket could show its inline error.
- They render their own tag with a markup id, so `target.add(field)` (or `target.add(form)`) re-renders them, e.g. to show inline errors in an Ajax `onError`. Attributes on that tag in your markup (e.g. `class`) are kept.
- `field.add(...)` sends validators and `AjaxFormComponentUpdatingBehavior`s to the wrapped input; other behaviors apply to the panel's own tag. `getField()` returns the wrapped `FormComponent`.
- Single-input fields (text, password, email, number, URL, search, tel, date, date-time, time, month, week, money, percent) take `setSuggestions(List<String> | IModel<List<?>>)` - values the browser suggests as the user types, from a native `<datalist>` (anything else can still be typed) - and `setPrefix(text)`/`setSuffix(text)` (a `String` or `IModel<String>`; `null` hides it): text addons such as `https://`, `kg` or `€` in Oat's input group. Without one the field renders as usual.
- Fluent setters (`setRequired`, `setLabel`, `setPlaceholder`, `addValidator`, `add`, and `setMin`/`setMax` on number/range fields) return the concrete field type, so they chain freely.

- `checkBoxMultipleChoice(id, label, model, choices, renderer?)`: `OatCheckBoxMultipleChoice`, a checkbox group bound to an `IModel<? extends Collection<T>>` of the selected choices (updated in place); `setInline(true)` for a row.
- `listMultipleChoice(id, label, model, choices, renderer?)`: `OatListMultipleChoice`, a `<select multiple>` bound to a collection of the selected choices; `setMaxRows(n)` sets its height.

- `fileDropzone(id, label, model)`: Drag-and-drop alternative to `fileUpload`.
- `moneyField(id, label, model)`: `OatMoneyField`, an amount bound to a `BigDecimal`, shown and parsed in the user's locale (`1.234,50` / `1,234.50`, `inputmode="decimal"`). `setCurrency(Currency | IModel<Currency>)` sets the decimals (2 for EUR, 0 for JPY; input is rounded half-even) and the symbol, shown before or after the amount as the locale puts it; the user may type the symbol too. `setMin`/`setMax` take `BigDecimal`s.
- `percentField(id, label, model)`: `OatPercentField`, a `BigDecimal` holding the number as shown (19 means 19%), with a `%` suffix; `setFractionDigits(n)` (default 2), `setMin`/`setMax`.
- `dateRangeField(id, label, model)`: `OatDateRangeField`, a `DateRange(from, to)` (`LocalDate`s, either may be `null`; `contains(day)`) edited as two date inputs in an input group, named "From"/"To". `setRequired(true)` needs both ends; an end before the start fails with `OatDateRangeField.order`.
- `autoCompleteField(id, label, model)`: `OatAutoCompleteField<T>`, Wicket's `AutoCompleteTextField` with an Oat-styled list: `setChoices(text -> service.search(text))` (called as the user types; `setMaxChoices(n)`, 10 by default), `setDisplay(T::name)`. On submit the text must match a suggestion (exactly, else ignoring case) and the value is that object; otherwise `OatAutoCompleteField.noMatch`. `setFreeText(text -> value)` accepts other text.
- `customField(id, label, model, (id, model) -> input)`: `OatCustomField<T>`, an Oat field (legend, hint, inline errors, required mark, label from `.properties`/model from a `CompoundPropertyModel` when left out) around your own input made of several inputs, usually a `FormComponentPanel<T>`. Every form component inside gets `aria-describedby` (the hint/error) and `aria-invalid`; give each its own `aria-label`.
- `tagInput(id, label, model)`: Tag/chip input bound to an `IModel<List<String>>`. Tags are trimmed and de-duplicated; no tags is an empty list (and fails `setRequired(true)`). As in Oat's widget, a comma separates tags, so a tag can't contain one.

- `fieldset(id, legend?)`: `OatFieldset`, a titled form section. A `Border`, so it goes on a `<fieldset wicket:id="...">` whose content it wraps; `add(...)` puts components inside it, and fields there still inherit a parent `CompoundPropertyModel`. The legend is looked up by id when left out; `setDescription(text)` adds a line under it. Add `Oat.Behaviors.row()` to lay out its fields on the grid.

## Data & Feedback
- `statCard(id, label, value)`: `OatStatCard`, a `Border` (e.g. on an `<article>`) showing one key figure: label, value in large type (numbers grouped in the user's locale; pass a `String` model for amounts), and optionally `setTrend(IModel<List<Number>>)` - a sparkline under it - and `setChange(IModel<Number> percent)` - a badge such as `+12.5%`, green for a rise and red for a fall, or the other way round with `setChange(model, false)` - and `setHint(model)`, e.g. "vs. last month". Its tag's content is shown below the figure.
- `descriptionList(id, model?)`: `OatDescriptionList` on a `<dl>`: a record's fields as label/value pairs, labels beside values (stacked on narrow screens). `addProperty("customer.name")` reads a property of its model, labelled by the `.properties` entry with that key; `addItem(label, valueModel)`; `addItem(labelModel, id -> component)` for a badge or link. Numbers and dates follow the locale; an empty value shows "—".
- `timeline(id, eventsModel, Event::title, Event::time)`: `OatTimeline`, events in the given order along a line, each with a marker, title, time (any `java.time` value, localized, in a `<time datetime>`; `null` leaves it out) and `setDescription(fn)`; `setVariant(fn)` colors a marker (`SUCCESS`, `WARNING`, `DANGER`).
- `messageList(id, messages, Msg::author, Msg::text, Msg::time)`: `OatMessageList<T>`, comments or notes in order: avatar (initials of the author, or `setAvatar(m -> imageUrl)`), author, time (`java.time`, localized `<time datetime>`), escaped text keeping line breaks. Has a markup id for `target.add(list)`.
- `messageInput(id, (target, text) -> ...)`: `OatMessageInput`, a text area (named by `OatMessageInput.label`) and a Send button (busy); sends the stripped text, ignores blank ones, then empties the box.
- Data table extras: `new OatRowDetailsColumn<>((id, rowModel) -> panel)` expands a row into a full-width panel under it (created on first open, rendered on a `<div>`; expanded rows kept by `equals`, `isExpanded/setExpanded`). `new OatEditableColumn<T, S, V>(header, sort, getter, setter)` with `.setType(Integer.class)`, `.setRequired`, `.addValidator`, `.onSave((target, row) -> ...)`: a button that becomes a field with Save/Cancel (Enter saves, Escape cancels via `wicket-oat.js`, errors inline). On `OatDataTable`: `setColumnChooser(true)` (a "Columns" popover; `setColumnVisible(index, bool)`), `setCsvExport("file.csv")` ("Export CSV", `OatCsvExport.write(provider, columns, locale, out)`: `IExportableColumn`s with a header, plain numbers, ISO dates, CSV-injection-safe). Each row is a `<tbody class="oat-row">`; `OatDataTable.Row#getDetails()`.
- `loadMoreList(id, IDataProvider, batchSize, (id, itemModel) -> component)`: `OatLoadMoreList<T>`, a list (`role="list"`) showing a batch at a time; "Load more (20 of 64)" (`OatLoadMoreList.more`) appends the next one over Ajax without re-rendering the rest. `setLoadOnScroll(true)` loads as the button comes into view, including inside a scrolling pane. Call `reset(target)` after the data changes. Keeps loaded rows in the page, so it suits hundreds of items, not tens of thousands.
- Charts in `dev.jbaby.wicket.oat.components.chart`, all server-side SVG with a title (`setTitle`), hover values, a "Data" table (`OatChart.data`; `setCategoryHeader(model)` names its first column) and `setValueFormat((number, locale) -> text)`. The colors are `--oat-chart-1..8`, stepped for light and dark:
  - `barChart(id, items, Item::name, Item::value)`: horizontal bars, with the name before each bar and the value after it. Values ≥ 0.
  - `columnChart(id, items, Item::label, Item::value)`: columns for ordered categories. The highest and the last column are labelled; at most 8 x-axis labels.
  - `lineChart(id, items, Item::label).addSeries(name, Item::value)`: up to 3 series (`MAX_SERIES`), with a legend from two on. A single series gets an area and its last value labelled; a `null` leaves a gap.
  - `donutChart(id, items, Item::name, Item::value)`: a ring with the total, and a legend of values and shares; above 6 parts the smallest become "Other" (`OatChart.other`). The table keeps every item.
  - `sparkline(id, IModel<List<Number>>)`: a small trend line without axes (decorative, `aria-hidden`), with the latest value as a dot. `OatStatCard.setTrend(model)` adds one under the figure.
- `icon(id, name)`: `OatIcon`, inline SVG from 64 Lucide icons (`OatIcon.names()`: pencil, trash-2, plus, search, mail, ...), 1em at the text's color. On `<svg wicket:id>` or any tag (the SVG goes inside). Decorative (`aria-hidden`) unless you `setLabel(text)`; add your own with `OatIcon.register(name, "<path d=...>")`.
- `cookieConsent(id)`: `OatCookieConsent`, a card fixed at the bottom with Accept / Only necessary (`OatCookieConsent.*` texts); `setPolicyLink(PageClass)`, `onAnswer(accepted -> ...)`. The answer is stored for a year in the `oat-cookie-consent` cookie (HttpOnly, SameSite Lax). Check it with `OatCookieConsent.isAccepted()` / `isAnswered()`.
- `lazyLoad(id, id -> component)`: `OatLazyLoadPanel`, Wicket's `AjaxLazyLoadPanel` with Oat skeletons (3 lines by default; `setPlaceholder(Shape, count)`) while the content loads over Ajax right after the page (0.1 s). Subclass it to override `isContentReady()` and wait for background work, polled every `getUpdateInterval()`.
- `feedbackPanel(id, filter?)`: `OatFeedbackPanel`, a Wicket `FeedbackPanel` rendering each `info()`/`success()`/`warn()`/`error()` message as an Oat alert of the matching variant. It adds itself to Ajax responses when it has messages to show or clear, so no `target.add(feedback)` is needed. By default it leaves out errors Oat form fields already show inline (`NotShownInlineFilter`); pass `null` to show everything.
- `dataTable(id, columns, dataProvider, rowsPerPage)`: `OatDataTable`, a styled Wicket DataTable, paged with `OatPagingNavigator`; sortable headers show an arrow and set `aria-sort`. It has a markup id (`target.add(table)`; `getTable()` is the inner `DataTable`). Use `setEmptyState(id -> emptyState(id, "No results"))` for a custom placeholder when it has no rows, and `setToolbar(id -> component)` for a toolbar above it (e.g. a search form; in its Ajax handler `table.getTable().setCurrentPage(0); target.add(table.getTable())`); both factories must use the id they are given. With an `OatSelectionColumn`, `addBulkAction(label, (target, rows) -> ...)` / `addBulkAction(IModel label, OatVariant, ...)` add buttons to a bar shown while rows are selected ("3 selected", the actions, "Clear selection"); actions get a copy of the selected rows and should call `clearSelection(target)` when done.
- Columns in `dev.jbaby.wicket.oat.components.table` (all take a header model, an optional sort property and a lambda for the value):
  - `OatLinkColumn.toPage(header, sort, label, PageClass, row -> pageParameters)` / `OatLinkColumn.onClick(header, sort, label, (target, row) -> ...)`.
  - `new OatBadgeColumn<>(header, sort, value, row -> OatVariant)`: the value as a badge colored per row, e.g. a status.
  - `new OatNumberColumn<>(header, sort, value)`: locale-formatted and right-aligned; `.setFractionDigits(min, max)`, `.setCurrency(Currency)` or `.setCurrency(Row::currency)` for amounts.
  - `new OatDateColumn<>(header, sort, value)`: any `java.time` value in the locale's style (dates `MEDIUM`, times `SHORT`); `.setStyle(date, time)`, `.setPattern("yyyy-MM-dd")`, `.setZone(zone)` for `Instant`s.
  - `new OatBooleanColumn<>(header, sort, value)`: a read-only checkbox named after the column.
  - `new OatActionsColumn<>()`: a "⋯" menu per row; `addAction(label, (target, row) -> ...)` returns the action for `.setVariant(OatVariant.DANGER)` (shown in red) and `.setVisibleWhen(row -> ...)`. A row without visible actions shows no button.
  - `new OatSelectionColumn<>(IModel<? extends Collection<T>> selection)`: row checkboxes plus a "select all on this page" box in the header; kept across pages and sorting, compared with `equals`. Sends `OatSelectionColumn.SelectionChanged` (bubbling) on every change.
- `progress(id, value, max?)`: Standard `<progress>` bar; `max` is an optional bound model.
- `meter(id, value)`: Simple `<meter>`.
- `meter(id, value, min, max, low, high, optimum)`: Advanced `<meter>` with full range/zone control.
- `spinner(id, size?)`: Loading indicator.
- `skeleton(id, shape?)`: Placeholder for loading content.

## Usage Example
```java
add(Oat.Components.button("myBtn", "Save", target -> {
    // Save logic
    Oat.toast(target, "Saved!", OatVariant.SUCCESS);
}));
```
