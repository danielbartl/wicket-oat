# Wicket Oat Components

Oat components are plain Wicket components: create them with `new`. Those driven by a callback (`OatButton`, `OatSubmitButton`, `OatAccordion`, `OatTabs`, `OatDropdown`, `OatButtonGroup`, `OatBreadcrumb`, `OatPagination`, `OatAvatarGroup`, `OatWizard`, `OatLoginForm`, `OatLazyLoadPanel`) also have a static factory taking a lambda instead of a subclass, like Wicket's `AjaxLink.onClick(...)`, listed below; `Oat.Components` has the same factories under one roof (`Oat.Components.button(...)`, `accordion(...)`, ...).

## Variants
Colors are a single `dev.jbaby.wicket.oat.OatVariant` enum everywhere (alerts, badges, buttons, toasts): `DEFAULT`, `SECONDARY`, `SUCCESS`, `WARNING`, `DANGER`. Buttons style `SECONDARY`/`DANGER`; badges all; alerts and toasts `SUCCESS`/`WARNING`/`DANGER`. There are no per-component `Variant` enums.

## General
- `new OatAlert(id, message?, variant?)`: Creates an `OatAlert`. `message`/`variant` can each be a plain value, an `IModel`, or omitted.
- `new OatBadge(id, label, variant?)`: Creates an `OatBadge`. `label` can be a `String` or an `IModel<?>`.
- `OatButton.onClick(id, label, onClick)`: Creates an `OatButton` with an Ajax click handler, on an `<a>` or `<button>`. The label is rendered as the tag's text, so the markup is just `<a wicket:id="save"></a>` (no inner `<span wicket:id="label">` - that now fails). `new OatButton(id) { onClick... }` without a label renders the markup body instead, e.g. an icon with `setIcon(true)`.
- `new OatSplitButton(id, label, onClick)`: `OatSplitButton`, a button for the usual action joined to a "▾" button with a menu of related ones (Oat's `menu.buttons`). `addAction(label, target -> ...)` returns the entry for `.setVariant(OatVariant.DANGER)`; `setVariant`/`setStyle`/`setSize` apply to both buttons. The "▾" button is named by the `OatSplitButton.more` resource ("More actions").
- `OatSubmitButton.onSubmit(id, label, onSubmit, onError?)`: Creates an `OatSubmitButton`, an Oat-styled `AjaxButton` that submits its form: `onSubmit` runs when the form is valid, `onError` when it isn't (e.g. `target -> form.error("Please fix the errors.")`); Oat fields show their own errors without it. Markup: `<button wicket:id="save"></button>`. Subclass `OatSubmitButton` directly to override `onSubmit`/`onError` instead.
- For slow actions, `setBusyIndicator(true)` on either button (off by default) shows a spinner (`aria-busy`) while its Ajax request runs and ignores further clicks, so the action can't run twice. `OatDialog.setBusyIndicator(true)` does it for the dialog's confirm button, and `Oat.Behaviors.ajaxBusy()` for other Ajax links and buttons.
- `new OatCard(id)`: Creates an `OatCard` container.
- `new OatAvatar(id, urlModel)` / `new OatAvatar(id, initials)` / `OatAvatar.initials(id, initialsModel)`: Creates an `OatAvatar` from just an image URL or just initials. Note `new OatAvatar(id, model)` takes a picture URL, not initials.
- `new OatAvatar(id, urlModel, initialsModel, size)`: Creates an `OatAvatar` with a picture over initials, which show while it loads and if it can't be loaded (Wicket Oat's script hides a failed picture); `size` is required in this overload. The models are read once on every render; a blank URL is no picture. `OatAvatar.initialsOf("Ada Lovelace")` gives `"AL"`.
- `OatAvatarGroup.of(id, model, size?, populateItem)`: Creates an `OatAvatarGroup` (a clustered/overlapping set of avatars).
- `new OatEmptyState(id, title, message?)`: Creates an `OatEmptyState` placeholder.

## Layout & Navigation
- `OatAccordion.of(id, model, exclusive?, populateItem)`: Creates an `OatAccordion`.
- `OatButtonGroup.of(id, model, populateItem)`: Creates an `OatButtonGroup` container for buttons.
- `OatBreadcrumb.of(id, model, populateItem)`: Creates an `OatBreadcrumb` trail, a panel on `<nav wicket:id="...">` (with nothing inside: it brings its own markup) named by the `OatBreadcrumb.label` resource ("Breadcrumb"; `setLabel(...)` or an `aria-label` in the markup for another name). Not shown without levels. `populateItem` adds each level's `link` with a `label` child; the last is marked `aria-current="page"`, or `setCurrent(titleModel)` ends the trail with the current page as text. `setMaxItems(n)` (at least 2, counting the current page) leaves levels out of a longer trail: the first, a "…" button (`OatBreadcrumb.more`, "Show more levels") whose menu has the levels in between (populated the same way, as `role="menuitem"` links), and the last ones. The levels are read once per request; each list item's id and model index is the level's index among all of them (`breadcrumb:list:tail:4:link`).
- `new OatPagingNavigator(id, pageable)` / `new OatAjaxPagingNavigator(id, pageable)`: `OatPagingNavigator` / `OatAjaxPagingNavigator`, Wicket's (Ajax)`PagingNavigator` rendered as Oat pagination for any `IPageable` (`DataView`, `PageableListView`, `DataTable`). Prefer these whenever there is an `IPageable`. For the Ajax one, the pageable or a parent needs `setOutputMarkupId(true)`. For a `DataTable` of your own, `table.addBottomToolbar(new OatNavigationToolbar(table))` and `table.addTopToolbar(new OatHeadersToolbar<>(table, provider))` (in `components.table`) give it `OatDataTable`'s Ajax paging row and `aria-sort` headers.
- `OatPagination.of(id, model, populateItem)`: Creates an `OatPagination` control - hand-rolled page links for when there's no `IPageable`; you style the current page yourself. The `<nav>` is named by `OatPagination.label` ("Pagination"), unless its markup has an `aria-label`.
- `OatDropdown.of(id, triggerLabel, model, label, onClick)`: Creates an `OatDropdown` popover menu whose items show `label.apply(item)` and run `onClick(target, item)` over Ajax when chosen; the menu then closes.
- `OatDropdown.of(id, triggerLabel, model, populateItem)`: The same with items you populate yourself (each is a `<button role="menuitem">` with a `"label"` child); call `dropdown.close(target)` after handling a click.
- `new OatTabbedPanel<>(id, tabs)`: Creates an `OatTabbedPanel`, Wicket's `AjaxTabbedPanel` with Oat styling. Tabs are `ITab`s - build them with `Oat.tab("Title", SomePanel::new)` (the factory receives the panel id). Only the selected tab's panel is created, and switching swaps it over Ajax; `new OatTabbedPanel<>(id, tabs, selectedIndexModel)` keeps the selection in your own model. Prefer this for panels that are expensive or need server state.
- `OatTabs.of(id, model, populateTab, populatePanel)`: Creates an `OatTabs` tab strip + panels, all rendered up front and switched in the browser by the `ot-tabs` web component.
- `new OatDialog(id, header)` / `new OatDialog(id, triggerLabel, header)`: Creates an `OatDialog` modal on the native `<dialog>` element. It works like Wicket's `ModalDialog`: set the content with `setContent(component)` - the component must use the id `OatDialog.CONTENT_ID` - and open and close it from any Ajax handler with `dialog.open(target)` / `dialog.close(target)` (`open` re-renders it first); `open(content, target)` sets content that is removed again on close. With a trigger label it also renders a button that opens it in the browser. The server tracks `isOpen()`: Cancel, Escape and a click on the backdrop close it in the browser and tell the server, the overridable `onClose(target)` runs once whenever it closes (also after a confirm or `close`), and `target.add(dialog)` keeps an open dialog open. The content sits in the dialog's own form, so fields in it are validated when Confirm is clicked: on a validation error the dialog stays open and shows them inline; otherwise the overridable `onConfirm(target)` runs and the dialog closes unless an error was reported in it there (e.g. `field.getInput().error("Taken")`) or it was opened again there (e.g. for the next record). Put it on a tag of its own (`<div wicket:id="dialog"></div>`, no box of its own) so `target.add(dialog)` works; on `<wicket:container>`, which deployment mode strips, only `open`/`close` do. Inside a page's form its buttons render as `type="button"` (`NestedFormButtonBehavior`, also on `OatSubmitButton`), so Enter in a page field can't click them. `OatConfirmDialog` ignores Confirm clicks while an answer is handled. `setConfirmLabel`, `setCancelLabel` and `setConfirmVariant(OatVariant.DANGER)` customize the buttons; the default labels come from the `OatDialog.confirm` / `OatDialog.cancel` resource keys. `setCloseButton(true)` adds an "×" in the header's corner (named `OatDialog.close`; first in the markup, and wicket-oat.js focuses the first field on opening), and `setFooterVisible(false)` leaves out the footer with Cancel and Confirm (Enter in a field then submits nothing). The content scrolls between header and footer. Closed in the browser, the dialog's fields show the models again next time (input not confirmed and errors are dropped; the server is told once the dialog is out of sight). An open dialog rendered again shows without animating in again. `getDialogElement()` is the `<dialog>`, for a subclass.
- `new OatDrawer(id, header)` / `new OatDrawer(id, triggerLabel, header)`: `OatDrawer`, an `OatDialog` (same API: `setContent`, `open`/`close`, `onConfirm`/`onClose`, Cancel/Confirm) that slides in from an edge as a side panel, for filters, a record's details or an edit form: `setSide(OatDrawer.Side.END)` (default; as tall as the screen, `min(24rem, 100% - 3rem)` wide), `START`, or `BOTTOM` (as wide as the screen, up to 85% of its height); start and end follow the text direction. It has the "×" by default; the content scrolls between header and footer, which stays at the bottom. For a drawer that only shows something, `setFooterVisible(false)`. Its setters return `OatDrawer`, so they chain with `setSide`.
- `new OatPageHeader(id, title)`: `OatPageHeader`, a `Border` on a `<header>`: breadcrumb, title (`<h1>`, looked up by id when no title is given) and subtitle on one side, and the tag's own content as the actions on the other (wrapping below on narrow screens). `setSubtitle(...)`, `setBreadcrumb(List<MenuItem> | IModel<List<MenuItem>>)` - links to the pages above, ending with the title as the current page (`aria-current`), in a `<nav>` named as any `OatBreadcrumb`; it is one, and `setBreadcrumbMaxItems(n)` leaves levels of a long one out.
- `new OatPopover(id, triggerLabel, id -> content)`: `OatPopover`, a button opening a panel with any content (an `ot-dropdown` with a popover), e.g. a filter or quick-edit form; the factory must use the id it is given (`OatPopover.CONTENT_ID`). `close(target)`, `getContent()` to re-render it, `getTrigger()`.
- `OatWizard.onFinish(id, target -> onFinish)` / `new OatWizard(id) { onFinish(target) }`: a form over several steps with numbered steps (`aria-current="step"`; finished steps are links back). `addStep(title, id -> component)` - created when the step is shown, so keep data in a shared object; it is rendered on a `<div>`. Next validates the step's fields inline (Enter does the same; Finish on the last step); Back and step numbers go back without validating. Override `onNext(step, target)` and report an error on a component to keep the user on a step. `getCurrentStep()`/`setCurrentStep(i)`. Texts: `OatWizard.back`/`.next`/`.finish`, step list named by `OatWizard.steps`.
- `OatLoginForm.signIn(id, (user, pass) -> boolean)` / `new OatLoginForm(id) { signIn(user, pass, rememberMe) }`: username (`autocomplete="username"`), password (`current-password`), Sign in (busy). A failed attempt shows `OatLoginForm.failed` without saying which part was wrong and clears the password; a successful one gives the session a new id (`changeSessionId()`, keeping its metadata) and calls `onSignedIn(target)` (default: `continueToOriginalDestination()`, then the home page). `setRememberMe(true)` shows the checkbox, `setForgotPasswordLink(PageClass)` a link. The core doesn't depend on `wicket-auth-roles`; call e.g. `AuthenticatedWebSession.get().signIn(...)` in `signIn`.
- `new OatCrud<>(id, columns, provider, rowsPerPage)`: `OatCrud<T, S>`, an `OatDataTable` plus "New" (with `setNewItem(Supplier)`), Edit and Delete in an actions column, an edit `OatDialog` and an `OatConfirmDialog`. `setEditor((id, model) -> panel)`: the panel gets a `CompoundPropertyModel` over the record (pass it to `super(id, model)`; Oat fields named after properties bind by themselves). `setOnSave((target, record) -> ...)` runs after a valid save (report an error on a field to keep the dialog open), `setOnDelete(...)` after confirming; `setTitle(Record::name)` names it in "Edit {0}" / "Delete {0}?"; `setSearch(id -> component)` beside "New" (its Ajax handler re-renders just the rows: `target.add(crud.getDataTable().getTable())`); `getDataTable()`, `create(target)`, `edit(target, record)`. Edits load the record via `provider.model(...)`. Texts `OatCrud.*`.
- `new OatTree<>(id, ITreeProvider)`: `OatTree<T>` (`components.tree`), Wicket's `NestedTree` styled with Oat (`.oat-tree`, no theme images). `setLabel(fn)`, `setIcon(node -> iconName)`, `setOnSelect((target, node) -> ...)` (labels become links, `aria-current` on the selected one; `select(target, node)`). Expand buttons are `<button>`s with `aria-expanded` and `OatTree.expand`/`collapse` labels ("Expand {0}"). Nodes are compared by the provider's models (`equals`).
- `new OatTableTree<>(id, columns, ITreeProvider, rowsPerPage)`: `OatTableTree<T, S>`, a tree grid (Wicket's `TableTree`); put a `new TreeColumn<>(Model.of("Name"))` among the columns, other columns as in a data table. Oat headers (`aria-sort` with an `ISortableTreeProvider`), paging, `OatTableTree.empty`; `setLabel`, `setIcon`, `onSelect`. Focus returns to a node's button after toggling.
- `new OatMenuBar(id)`: `OatMenuBar`, a row of small ghost buttons (`setStyle(ButtonBehavior.Style)` to change). `addAction(label, target -> ...)`, `addLink(label, PageClass[, params])` (it has `aria-current` while that page is shown), `addMenu(label)` returns a `Menu` with `addAction(label, ...)` / `addAction(IModel label, OatVariant.DANGER, ...)`. Put it on a `<nav aria-label="...">`.
- `new OatSplitLayout(id, id -> first, id -> second)`: `OatSplitLayout`, two panes, each scrolling on its own. The first is resizable with the browser's own corner handle (CSS `resize`, no JS). `setSplit(20..80 in steps of 10)` sets its starting share; `setOrientation(VERTICAL)` stacks them (28rem high by default). Below 768px they are stacked and not resizable. The factories must use the ids they are given (`first`, `second`).
- `new OatMasterDetail<>(id, selectionModel)`: `OatMasterDetail<T>`, a list beside the selected item's details. `setMaster(id -> component)` (any component; it calls `select(target, item)` and can use `isSelected(item)`), `setDetail((id, itemModel) -> component)`; an empty state (`OatMasterDetail.empty`) while none is selected. Below 768px one shows at a time, with a Back button (`OatMasterDetail.back`, `showList(target)`); switching keeps the list's scroll position.
- `new OatConfirmDialog(id)`: `OatConfirmDialog`, an `OatDialog` that asks before an action runs. Add one per page and call `confirm.ask(target, header, message, t -> action)` from any Ajax handler (`String` or `IModel<String>` texts; `message` may be `null`); the action runs on Confirm, at most once, and Cancel/Escape closes without running it. One dialog serves any number of buttons. The confirm button is `DANGER` by default; `setConfirmLabel`, `setCancelLabel`, `setConfirmVariant`, `setHeader` and `setBusyIndicator` return `OatConfirmDialog`, so they chain with `ask`.
- `OatAppLayout`: (Base Page) Provides sidebar and topnav, and applies the current theme. Subclasses pass `PageParameters` (or a model) to `super(...)`; override `sidebarMenuItemsModel()` to return `MenuItem`s - `MenuItem.of(label, PageClass)` or `MenuItem.of(label, PageClass, pageParameters)`, with a `String` or `IModel<String>` (e.g. `ResourceModel`) label. `MenuItem.group(label, items...)` makes a collapsible section of links (open while one of its pages is shown; groups can't be nested), and `item.withBadge(IModel<?> | String)` adds a badge after a link's label, read on every render and hidden while `null`, empty or zero (e.g. `withBadge(() -> orders.countOpen())`). The sidebar has a markup id, so `target.add(getSidebar())` re-renders it, e.g. to update badges. Items for pages the user isn't authorized to instantiate are left out (and a group left empty), and an item is active when the page class (and its parameters, if any) match. It sets `lang` on `<html>` from the page's locale and starts with a "Skip to content" link (`OatAppLayout.skipToContent`) to `<main id="oat-main">`, shown only while focused. The title, name and menu-button label default to the `OatAppLayout.title` / `OatAppLayout.name` / `OatAppLayout.toggleMenu` resources; override `appTitleModel()`/`appNameModel()`, `newTopNavExtra(id)`, `newSidebarFooter(id)` and `newMenuLink(id, item)` (e.g. an `AjaxLink` instead of the default `BookmarkablePageLink`) to customize.
- `new OatBottomNav(id, List<BottomNavItem>)` / `new OatBottomNav(id, IModel<List<BottomNavItem>>)`: a tab bar fixed to the bottom of a phone's screen, on a `<nav>` (named "Main" by `OatBottomNav.label`; `setLabel(...)` or an `aria-label` in the markup to change it). Three to five tabs, each an icon above a short label: `BottomNavItem.of(label, PageClass[, params])` with `withIcon(Icon.sprite("symbol-id") | Icon.svg("<svg>...</svg>") | Icon.named("calendar"))` - a symbol of the page's own SVG sprite (`<svg><use href="#id"/></svg>`), trusted inline SVG (not escaped: never user input), or an `OatIcon` name; draw sprites and SVGs with `currentColor`. `withBadge(() -> count)` shows a count on the icon, hidden while `null` or 0. `asPrimary()` makes one item the bar's main action, a round Oat `a.button` (`button oat-fab`) showing only its icon (the label becomes `aria-label`; it needs an icon) and never colored as the current tab. The current tab gets `aria-current="page"` (same page class, and parameters if the item has any); `withActive(page -> ...)` replaces that rule, e.g. `page -> page instanceof TeamPage || page instanceof MemberPage`. Tabs for pages the user isn't authorized to instantiate are left out. Hidden above 768px unless `setAlwaysVisible(true)`. Override `newLink(id, item)` to return another `AbstractLink` (e.g. an `AjaxLink`). Its rules are in `wicket-oat.css`; content under it needs `padding-block-end: calc(var(--oat-bottom-nav-height) + env(safe-area-inset-bottom, 0px))`, and the viewport meta tag needs `viewport-fit=cover` for the iPhone's safe area.
- `new OatUserMenu(id, nameModel)`: `OatUserMenu`, the signed-in user's menu for `OatAppLayout#newTopNavExtra`: picture (`setPicture(urlModel)`) or initials and name on a button named "Account: <name>" (picture only on phones), opening their name, `setDetail(model)` (e.g. email), `addLink(label, PageClass[, params]).setIcon("settings")` links (the current page's marked `aria-current`) and "Sign out". The name model returns `null` while nobody is signed in; then it shows a "Sign in" link to `setSignInPage(PageClass)` (hidden on that page), or nothing. "Sign out" (a POST from a stateless form, which also works after the session expired; refused with 403 when the browser's `Sec-Fetch-Site` says another site's page sent it) calls `signOut()` (default: `getSession().invalidate()`, which takes effect at the end of the request) and `onSignedOut()` (default: home page; go to a page with `setResponsePage(PageClass)`); override them, e.g. for Spring Security. Override `isSignedIn()` for a signed-in user without a name. The models are read once per request. Keeps pages stateless; has a markup id for `target.add(userMenu)` after an Ajax sign-in. Texts: `OatUserMenu.account`/`signIn`/`signOut`.
- `OatMobileLayout`: (Base Page) a phone-first page: the content in `<main class="oat-mobile-main">`, as wide as the bar's tabs (`--oat-bottom-nav-max-width`, 28rem) with room below, and an `OatBottomNav` after it. Override the abstract `bottomNavItemsModel()`; `newBottomNav(id, items)` to customize the bar (e.g. `setAlwaysVisible(true)`); the `bottomNav` field has a markup id for `target.add(getBottomNav())`. Applies the theme, density and `lang` like `OatAppLayout`, and its viewport meta tag has `viewport-fit=cover`.

## Form Components
- `new OatMultiSelectField<>(id, label, IModel<List<T>>)`: `OatMultiSelectField<T>`, an `OatCustomField` with chips (remove buttons named `OatMultiSelectField.remove`) and a search box (Wicket's `AutoCompleteTextField`): `setChoices(text -> list)`, `setDisplay(fn)`, `setMaxChoices(n)`. Choosing adds the value and clears the box; chosen ones aren't suggested again. Required means at least one. Chips added or removed are like typed input: they reach the model on submit, and `form.clearInput()` drops them (`OatDialog` does that on open and cancel), so one dialog can be reused per record. Works inside an `OatDialog`/`OatPopover`, like `OatAutoCompleteField`: `wicket-oat.js` shows Wicket's suggestion list above them (Escape closes the list, then the dialog).
Form fields are `Oat[Type]Field` classes in `dev.jbaby.wicket.oat.components.form` (`OatTextField`, `OatEmailField`, ...), except `OatTextArea`, `OatDropdownChoice`, `OatCheckBox`, `OatSwitch`, `OatFileUpload`, `OatFileDropzone` and `OatTagInput`.

Every one takes an optional trailing hint-text model — but only when `label` is passed as an `IModel<String>`, not a plain `String`:
`new Oat[Type]Field(id, IModel<String> labelModel, model, hintModel?)`. There is no `(id, String label, model, hintModel)` overload; wrap the label in `Model.of("Label")` if you need a hint.

The label and the model can also be left out, exactly like plain Wicket form components: `new Oat[Type]Field(id)` inherits the model from a parent `CompoundPropertyModel` by id, and `new Oat[Type]Field(id, model)` keeps an explicit model. A missing label is looked up in the `.properties` files with the id as the key (falling back to the id). `OatDropdownChoice` mirrors `DropDownChoice`: `(id, choices, renderer?)` and `(id, model, choices, renderer?)`.

Behavior of the field panels:
- Required fields get `aria-required="true"` and an asterisk after their label (via `data-required` on the field container). The native `required` attribute is deliberately not set, since the browser would block the submit with its own message before Wicket could show its inline error.
- After an Ajax request that validates them (e.g. a submit) they show an error that appeared, changed or went away by themselves, without `target.add(...)`: they update their message and error state in place, so the input keeps its focus and what the user typed. Other Ajax requests leave the errors shown alone. They also render their own tag with a markup id, so `target.add(field)` (or `target.add(form)`) re-renders them. Attributes on that tag in your markup (e.g. `class`) are kept.
- The wrapped `FormComponent` is the field's child `input` (`BaseOatField.INPUT_ID`), so in a `FormTester` its path is `"<fieldId>:input"` (e.g. `formTester.setValue("email:input", ...)`), and `getInput()` returns it, e.g. for `setNullValid(true)` or `new EqualPasswordInputValidator(password.getInput(), repeat.getInput())`.
- `field.add(...)` sends validators and `AjaxFormComponentUpdatingBehavior`s (including `OnChangeAjaxBehavior` and `AjaxFormChoiceComponentUpdatingBehavior`) to the input; other behaviors apply to the panel's own tag. `addToInput(...)` adds any behavior to the input, e.g. `addToInput(AttributeModifier.replace("autocomplete", "email"))`. Subclasses create the input in `newInput(id, model)`.
- Single-input fields (text, password, email, number, URL, search, tel, date, date-time, time, month, week, money, percent) take `setSuggestions(List<String> | IModel<List<?>>)` - values the browser suggests as the user types, from a native `<datalist>` (anything else can still be typed) - and `setPrefix(text)`/`setSuffix(text)` (a `String` or `IModel<String>`; `null` hides it): text addons such as `https://`, `kg` or `€` in Oat's input group. Without one the field renders as usual.
- Fluent setters (`setRequired`, `setLabel`, `setPlaceholder`, `addValidator`, `add`, and `setMin`/`setMax` on number/range fields) return the concrete field type, so they chain freely.

- `new OatMoneyField(id, label, model)`: `OatMoneyField`, an amount bound to a `BigDecimal`, shown and parsed in the user's locale (`1.234,50` / `1,234.50`, `inputmode="decimal"`). `setCurrency(Currency | IModel<Currency>)` sets the decimals (2 for EUR, 0 for JPY; input is rounded half-even) and the symbol, shown before or after the amount as the locale puts it; the user may type the symbol too. `setMin`/`setMax` take `BigDecimal`s.
- `new OatPercentField(id, label, model)`: `OatPercentField`, a `BigDecimal` holding the number as shown (19 means 19%), with a `%` suffix; `setFractionDigits(n)` (default 2), `setMin`/`setMax`.
- `new OatDateRangeField(id, label, model)`: `OatDateRangeField`, a `DateRange(from, to)` (`LocalDate`s, either may be `null`; `contains(day)`) edited as two date inputs in an input group, named "From"/"To". `setRequired(true)` needs both ends; an end before the start fails with `OatDateRangeField.order`.
- `new OatAutoCompleteField<>(id, label, model)`: `OatAutoCompleteField<T>`, Wicket's `AutoCompleteTextField` with an Oat-styled list: `setChoices(text -> service.search(text))` (called as the user types; `setMaxChoices(n)`, 10 by default), `setDisplay(T::name)`. On submit the text must match a suggestion (exactly, else ignoring case) and the value is that object; otherwise `OatAutoCompleteField.noMatch`. `setFreeText(text -> value)` accepts other text. Works inside an `OatDialog`/`OatPopover` (`wicket-oat.js` lifts the list above them).
- `new OatCustomField<>(id, label, model, (id, model) -> input)`: `OatCustomField<T>`, an Oat field (legend, hint, inline errors, required mark, label from `.properties`/model from a `CompoundPropertyModel` when left out) around your own input made of several inputs, usually a `FormComponentPanel<T>`. Every form component inside gets `aria-describedby` (the hint/error) and `aria-invalid`; give each its own `aria-label`.
- `new OatTagInput(id, label, model)`: Tag/chip input bound to an `IModel<List<String>>`. Tags are trimmed and de-duplicated; no tags is an empty list (and fails `setRequired(true)`). As in Oat's widget, a comma separates tags, so a tag can't contain one. Text typed without Enter or a comma is submitted as a tag too. The label, hint/error and `setPlaceholder(...)` are on the visible text box (`"tags:taginput:text"` in tests); the tags are submitted in the hidden `getInput()` (`"tags:input"`).

- `new OatFieldset(id, legend?)`: `OatFieldset`, a titled form section. A `Border`, so it goes on a `<fieldset wicket:id="...">` whose content it wraps; `add(...)` puts components inside it, and fields there still inherit a parent `CompoundPropertyModel`. The legend is looked up by id when left out; `setDescription(text)` adds a line under it. Add `Oat.Behaviors.row()` to lay out its fields on the grid.

Numbers and dates follow the locale; an empty value shows "—".

The chips are the radio buttons of a Wicket `RadioChoice` in a `<fieldset>` named by `setLabel(model)` or the id looked up in `.properties` (falling back to the id); the arrow keys move between them. Choices are read once per request, `null` among them is left out, and a `null` model binds by the id to a parent `CompoundPropertyModel`. It has its own form, so it works anywhere, also in a page's form or an `OatDrawer`. In tests: post the chip's value for the choice's input name, `tester.getRequest().getPostParameters().setParameterValue(choice.getInputName(), "paid")`, then `executeAjaxEvent("filter:form:choice", "change")`.

The rows are read once per request; `setReuseItems(true)` for form fields in the rows (the parts must then read the row through its model). On any tag; has a markup id for `target.add(list)`.
- `new OatIndicator(id, IModel<?> count)` / `OatIndicator.status(id, IModel<OatVariant>, IModel<String> label)`: `OatIndicator`, a Border putting a badge (count or short word, hidden while `null`, 0 or empty; `setVariant(OatVariant.DANGER)`) on the top-end corner, or an `OatStatus` dot on the bottom-end corner (its color from `status`'s variant; `setVariant` throws there), of what is inside its tag (`<span wicket:id="inbox"><a wicket:id="link">Inbox</a></span>`; add the content with `indicator.add(...)`). `setCorner(Corner.TOP_START|...)`.
