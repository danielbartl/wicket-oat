Getting Started

Go from zero to a beautiful Oat-styled Wicket application in under 5 minutes.

1 Add Dependency

Add the following dependency to your pom.xml:

<dependency>
    <groupId>dev.jbaby</groupId>
    <artifactId>wicket-oat-core</artifactId>
    <version>0.0.1-SNAPSHOT</version>
</dependency>

2 Install the Library

Initialize Oat UI in your WebApplication.init() method. This registers global CSS/JS and configures the Content Security Policy.

@Override
protected void init() {
    super.init();
    
    // Auto-configures headers and CSP
    WicketOats.install(this);
}

3 Create Your Base Page

Extend OatAppLayout to get the sidebar, top navigation, and automatic theme support for free.

public class BasePage extends OatAppLayout {
    // That's it! Your markup should use <wicket:extend>
}

4 Use the Oat Factory

Use the central Oat class to add components or behaviors to your page.

// In your Page constructor
add(Oat.Components.button("myButton", "Click Me", target -> {
    Oat.toast(target, "Hello from Oat!");
}));

Core Concepts: Components vs. Behaviors

Wicket Oat offers two ways to build your UI. Understanding the difference is key to using the library effectively.

1. Oat Components

Self-contained widgets that manage their own internal markup.

  • Namespace: Oat.Components
  • Philosophy: "Give me an Alert"
  • Best for: Building UI quickly without worrying about HTML tags.
add(Oat.Components.alert("id", Variant.INFO));

2. Oat Behaviors

Addons that "Oat-ify" existing Wicket components via composition.

  • Namespace: Oat.Behaviors
  • Philosophy: "Make this look like an Alert"
  • Best for: Styling standard Wicket links, labels, or containers.
myLink.add(Oat.Behaviors.button());
Feature Component Behavior
Java Usage new OatAlert(...) comp.add(new AlertBehavior())
Markup Handled by Oat Handled by You
Flexibility Fixed Structure Highly Flexible
